# 切片档案／当前验收约定

> 按需实例化为项目中每片的永久记录，或复用已有 SPEC/RUN/独立章节；不要改写本模板来记录项目。后续片先保留编号、目标、依赖、阶段及批准范围，轮到实施才展开下列必要细节，不填空章节。

## 标识与进度（本片的状态来源）
- 稳定编号、名称、类型（业务/技术/基础）、所属模块：
- 项目总览入口、前置/后续依赖：
- 执行阶段（待澄清/待确认/已计划/开发中/待验证/已验证/已取消，或既有等义状态）：
- 阻塞原因、解除条件与需要谁处理（独立于执行阶段）：
- 验证状态、证据适用版本/环境（已通过/失败/未验证/需重验）：
- 部署状态/环境、客户验收状态及来源（未知就写未知，GREEN 不代替这两项）：
- 更新时间、执行方式与当前负责人（已知时）：

## 客户可读：为什么做、什么算完成
- 为什么改（问题、来源、期望收益）：
- 使用角色、入口、可观察行为与正常/适用拒绝或失败验收示例；一句反例说明本片不承诺什么：
- 当前做什么、不做什么，必须保持什么：
- 追问确认的关键决定、依据和非阻塞假设：
- 批准范围、来源及状态；选择方向不等于批准实施：

## AI 可继续：本片设计与证据
- 负责模块、为什么选它、相关基线/决定链接：
- 当前模块的对外操作、输入/结果、规则归属及关键失败行为；只记录变化，稳定契约引用基线：
- 实际受影响的数据/接口/状态/兼容性设计增量（不受影响则省略）；有必要局部整理时写观察到的障碍、最小范围和保留行为的验证：
- 必需检查与证据边界（模拟/回放/联调等），是否测试先行及必要说明：
- 验收项 → 实际检查/观察 → 结果 → 日志或报告入口 → 被测版本/工作区/环境：

## 执行、恢复与历史
- 当前小目标、已完成/剩余依赖、下一步与阻塞：
- 代码版本/工作区变化、有效与失效证据、模式切换事实：
- 本片完成结论、可操作的结果及实际运行/演示入口（技术片可用接口/命令输出）、环境、未验证边界和跨片联动状态；详细检查链接上方证据，不重复日志：
- 重开记录：原决定/证据 → 新需求或失败事实 → 修改决定 → 新验证；保留旧结论的时间和范围：

状态变化先更新本档案，再同步总览摘要；只在重要变化、验证或交接时更新，不抄对话全文。
完成/取消后保留本片档案及证据入口，不被下一片覆盖；归档移动需同步链接。小修复可关联到本片，不强制另建片。
