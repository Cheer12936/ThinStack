# 可见方案与确认

**方案可见 ≠ 需要确认。** 主文件中的短摘要适用于所有实际修改任务；本参考只在新项目、新业务、架构调整或确需展开设计时加载。不要为小修复全量加载方案参考。

## 先让用户知道准备怎么解决

首次实质修改前，在当前对话说明：**问题或目标结果、做法及依据、影响范围与不改什么、准备怎样验证**。复用当前验收约定，不新增 Solution Brief 文件、状态字段或审批阶段；只给文件链接、品牌开场或“我会解决”不算方案可见。

| 场景 | 展示方式 | 确认规则 |
|---|---|---|
| 明确局部修复 | 原因确认后给通常3～4行修复摘要 | 已授权范围内直接执行，不因展示新增确认 |
| 原因尚未明确 | 先说明待查事实和诊断边界，查明后给有依据的修复摘要 | 不为展示猜测根因，不绕过 FAST_FIX 预算 |
| 简单明确功能 | 短摘要覆盖目标、做法、边界和验收；不强制七个标题 | 已有具体方案批准或明确要求直接实施则继续；新业务仍遵循一次确认，不以“简单”自动豁免 |
| 新项目、新业务或架构调整 | 按下述七项展示真正影响决定的内容 | 沿用主文件授权规则；必要时确认一次 |
| 已批准切片续做 | 点明当前片、既定做法和本次验证，引用原方案 | 不重新展示全案或逐片确认；实质范围变化另行处理 |
| 明确的机械修改 | 一句话合并做法、边界与检查 | 不强制方案卡或额外停顿 |

“首次修改”也包括新增测试文件、配置变更、项目建档和数据写入。可以先做已授权的只读调查；若诊断需要先写复现测试或做隔离试验，先展示该步骤的目标、边界和验证，不必假装已经知道最终修法。纯问答不插入方案卡，设计/验证任务只说明授权内的产出或检查，不暗示将修复产品。用户明确限制输出形式时按其要求压缩或省略例行摘要，但不能跳过必要授权。

开工标识与摘要合并展示，不同时发送多张重复卡。实现路径或影响边界发生实质变化时，在执行变更前简述新事实、调整与验证；超出批准范围先取得相应授权。普通编辑不反复播报。结束时对照开工摘要给出实际结果、证据、环境和未完成项；不展示内部推理或未经验证的完成结论。

## 七项内容检查范围

七项均须考虑；实质决定和变化必须展示。已有有效设计可引用，不受影响内容可合并说明，不为完整性编造细节或反复写“无变化”。

1. **目标与用户结果**：谁最终能完成什么，成功后可观察到什么。
2. **范围与不做事项**：本次承诺、明确排除项和需要另行授权的范围。
3. **关键业务规则**：不能由实现者自行猜测的计算、身份、归属、权限、状态或失败规则。
4. **切片地图与顺序**：多个独立结果列目标、依赖和顺序；单一结果明确是一片即可，不按前端、后端、数据库拆分。
5. **当前片验收行为**：正常行为及适用的拒绝/失败行为，具体到能够判断成功或失败。
6. **实际设计变化**：只展开受影响的数据、接口、状态和模块边界，说明由哪个模块负责及选择理由。
7. **兼容性与验证证据**：需要保留的旧能力、最低充分检查、真实环境边界和仍缺少的证据。

初始化先明确跨片共享且代价高的决定，再详细设计当前片。未来片只保留目标、验收目标、依赖、顺序和批准状态，不提前填写页面、表结构或接口实现。

方案可以是一段连贯说明、表格或合并章节；形式不决定完整性。方案确认一次后，在同一批准范围内连续交付，不逐片重复确认。新事实改变重要业务规则、范围或高代价决定时，只重新确认受影响部分。

## 最小示例（事实须实际核对，不是固定话术）

已确认分页参数丢失后：

> 薄栈｜修复｜自主：已确认翻页时没有保留筛选参数。复用现有查询入口保留这些参数，不改数据库和权限规则；验证筛选后翻页、无结果和原有分页行为。按已授权修复范围执行。

明确要求“把按钮文案‘提交’改成‘保存’”：

> 仅替换按钮文案，不改点击行为；检查页面显示和改动差异后交付。
