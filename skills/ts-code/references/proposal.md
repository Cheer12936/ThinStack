# 可见方案内容底线

新项目、新业务功能或架构调整在实施前向用户展示关键方案。目标是让用户能判断“做什么、如何拆、凭什么完成”，不是恢复固定十三章模板。

## 七项内容检查范围

七项均须考虑；实质决定和变化必须展示。已有有效设计可引用，不受影响内容可合并说明，不为完整性编造细节或反复写“无变化”。

1. **目标与用户结果**：谁最终能完成什么，成功后可观察到什么。
2. **范围与不做事项**：本次承诺、明确排除项和需要另行授权的范围。
3. **关键业务规则**：不能由实现者自行猜测的计算、身份、归属、权限、状态或失败规则。
4. **切片地图与顺序**：多个独立结果列目标、依赖和顺序；单一结果明确是一片即可，不按前端、后端、数据库拆分。
5. **当前片验收行为**：正常行为及适用的拒绝/失败行为，具体到能够判断成功或失败。
6. **实际设计变化**：只展开受影响的数据、接口、状态和模块边界，说明由哪个模块负责及选择理由。
7. **兼容性与验证证据**：需要保留的旧能力、最低充分检查、真实环境边界和仍缺少的证据。

初始化先明确跨片共享且代价高的决定，再详细设计当前片。未来片只保留目标、验收目标、依赖、顺序和批准状态，不提前填写页面、表结构或接口实现。

方案可以是一段连贯说明、表格或合并章节；形式不决定完整性。方案确认一次后，在同一批准范围内连续交付，不逐片重复确认。新事实改变重要业务规则、范围或高代价决定时，只重新确认受影响部分。
