# 引导模式：按表现增加结构

主文件的范围、批准和风险底线不变；这里只限制当前执行步长，不增加一套审批系统。

## 进入依据
用户明确要求引导，可信的本任务能力评测显示需要引导，或执行中观察到：重复无效修复、无关大改、忘记约定/修改理由、测试与用户行为脱节。
例如连续两次相似修复没有新增证据，可作为信号，但不是固定次数门槛。记录可观察事实，不猜测服务端“降智”原因。
高风险不自动代表模型弱；工具不可用、缺凭据、测试基础设施故障应作为环境阻塞处理，不能靠加步骤解决。

## 当前片的最小脚手架
1. 恢复相关基线和当前约定，确认唯一待解决行为与不能破坏的边界。
2. 将行为和必要规格写成可执行的小目标；已有 BDD/规格足够就复用，不重新提问或写全文。
3. 选择一个最小一致修改及其可靠检查。适用时先写行为失败测试，再最小实现，再通过/重构；不适用时直接修改并即时观察。
4. 记录证据和下一步，再进入下一个小目标。修改与检查没有进展时更换诊断方法；不能同时扩改多个无关模块。

不要一次列出几十个机械步骤，也不强制每一步让用户确认。并行只用于互不写入同一契约/文件的独立已授权任务；最终需要集成证明。
没有可信检查时不能宣称完成：保留工作区、说明缺口、请求必要事实/工具或独立审查。无法获得独立审查时如实说明，不冒充已发生。

## 返回自主
出现连续有信息增量且验收通过的小目标、当前边界已清楚时，可在稳定检查点返回自主并记录原因。避免每一步来回切换；先前失败证据不能因切换被清空。
用户可指定优先自主，但不能关闭强制授权和证据底线。强弱模型共享交付标准；引导不豁免测试、不扩大权限。

这份文档不能自行监控模型或拦截工具。生产安全须由宿主权限、沙箱、测试和人工批准共同承担。
