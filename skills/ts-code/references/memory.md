# 记忆、验收约定与恢复

仅在新项目、长期/跨会话业务工作、重要规则改变或恢复任务时读取。记忆保存的是事实与决定，不是要求披露内部推理过程。

## 长期基线
沿用当前架构文件；没有时，新项目使用 docs/architecture/BASELINE.md。已有 ARCHITECTURAL_BASELINE.md 不迁移、不建立第二份。
最少保存：模块职责与依赖、统一业务术语、核心身份/数据归属、适用权限与重要不变量、关键决定及理由、来源/版本、批准状态和未决项。
仅包含实际相关内容；样式修复不需要先补齐全项目基线。模板见[薄基线](../assets/baseline-template.md)，不是强制章节表。
对既有项目从受影响的代码、测试、schema 与配置核对事实；只读测试不能写成已验证。区分 OBSERVED（现状）、VERIFIED（已执行证明）、APPROVED（批准规则）、PROPOSED（建议）、UNKNOWN（未知）。
旧代码可能有错，不能自动把现状升级为批准规则。保留变更前理由和被新决定替代的链接，不静默改写历史。
新项目或全局规则的依赖实现前保存确认的相关决定；已有项目只补当前必要差异。真正未决的安全/业务边界阻止相关实现，不用文件名或 READY 标签代替判断。
无写权限时提供可保存的基线与任务快照，明确记忆未落盘，不声称下次会记得；依赖缺失信息的工作暂停，独立授权工作可继续。

## 当前验收约定与记录
每次修改都能回答五件事：为什么改、用户可见结果、负责模块及为什么选它、必须保留的约束、验收证据。
长期切片将这些内容保存到既有 SPEC/RUN 或单个任务文件。模板见[任务记录](../assets/task-template.md)。小修复可只在对话中记录；中断前用现有记录保存恢复要点。
规格与证据可在一份文件中，不强制双文件。方案确认记录具体范围和用户批准来源，不把“准备好了”当成已批准。
保持单一任务入口；已有 docs/SLICES.md 和 Slice N 连续编号保留，新任务取下一个编号。无既有规则时自行选择一个稳定编号方案，不重编号历史任务。
阶段变化、受影响规则变化、验证后或中断前更新：当前切片、执行方式及切换原因、已完成/失败/未验证、工作区状态、下一步和阻塞。
只持久化重要决定和证据索引，不复制对话全文，不保存秘密、真实个人数据或模型内部推理。

## 恢复与防止反复改模块
恢复时读取任务入口、当前约定及涉及模块的基线；核对当前代码/工作区与记录是否一致。已有有效批准继续生效。
记录中的 GREEN 只是当时范围的快照；判断本次需求或代码变化具体影响哪些证明，不把历史完成自动当成当前有效，也不全部重做。
已完成模块只有新需求、真实故障、失效证据或相关规则变更才重开；记录“原理由 → 新事实 → 修改决定”。清理喜好、旧 TODO 或重新加载文档不是重写理由。
发现外部并发改动时先对比，不覆盖他人修改；交叉依赖重新验证，未影响部分继续复用。
