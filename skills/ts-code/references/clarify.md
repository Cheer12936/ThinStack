# 追问与行为澄清（BDD）

用途：类似“Grill Me”的设计访谈，只问透会导致产品或架构选错的决定。深度由影响和不确定性决定，不由问题数量决定；不依赖外部技能。

**本文件是 Grill 提问节奏、次数、检查点和停止条件的唯一运行规则来源。** 主文件和 README 只作入口；历史发布记录不覆盖现行规则，评测器预算不等于产品访谈规则。

## 触发与深度
角色、业务结果、规则、身份/数据归属、权限、首期范围或外部约束存在多种合理解释，且会改变当前切片或高代价决定时触发。“新增财会模块”这类只有领域名的请求应先澄清；明确 Bug、文案、样式和已有规则下清楚的小功能不强制追问。

### 初始化：全局决定先清楚，当前切片再详细
先从已有资料核对影响整体设计的决定；充分已知就复用，不因 PROJECT_INIT 标签强制访谈。仍有关键未知时深入追问，不以“最小充分”为由跳过系统性问题。
按实际适用项关注：
- 服务谁、首期可用结果、做与不做什么；跨片必须共同遵守的业务规则。
- 单组织或多组织、身份与数据归属、共享/隔离和权限执行边界。
- 现有系统/数据的衔接、外部接口、兼容或迁移约束。
- 在线/离线、部署限制、并发/延迟/可用性、数据保留与恢复；只明确会改变方案的目标，不臆造百万用户规模。

先明确这些约束及模块对外承诺，再为当前片细化行为、接口和失败处理。未来片的完整表结构、每个页面和函数实现后置；多个切片依赖的身份、规则或接口不能以“不是当前片”为由推迟。
“实现细节”不等于可忽略：若离线同步、事务边界、第三方限制等会改变架构，就提前解决。表名、私有函数拆分、样式值通常由代理在既有约束内决定；若项目已有兼容契约则仍须遵守。
业务优先级和不可逆取舍由用户确认；技术事实能查则查，技术方案由代理先分析并说明选择、代价和建议，不把框架问卷推给非技术用户。
技术可行性无法靠访谈确认时，说明需要验证的假设；取得相应试验授权后做最小隔离验证，不靠多问制造确定性，也不把试验授权当成生产实现或上线授权。

## 提问方式
**计数口径：** 一轮指一批提问及用户对这批问题的回答；一批可含多个独立问题，每题的选项不另算问题。FAST_FIX 的诊断问题、方案确认和评测代理调用分别计数，不套用为 Grill 总上限。

1. 先读取相关已给答案、当前约定、基线、代码与可用资料；不为一次提问全库扫描，不让用户代查，也不重复已回答的问题。
2. 把重要未知组织为决策依赖：先问业务结果与范围，再问影响它的归属、规则、架构边界，最后问当前交互；不随机扫清单，不穷尽未来设计树。
3. 默认一次一个关键问题；明显缺少项目方向时，首轮可合并最多 3 个能独立回答的上游问题。依赖上一答案的问题留到下一轮，不为节省轮数提前猜测。每题优先给 2–4 个具体选项并允许自定义；选项仅是帮助。
4. 简述“为何现在必须决定”和各选项主要影响；信息足够才推荐并说明前提，不把推荐当成批准，也不强迫给未知问题选答案。
5. 回答后简短复述决定并更新依赖。初始化完成两轮问答后形成信息检查点：已明确什么、还有什么阻断当前设计、下一问预期获得什么新信息。不要求至少问两轮；两轮不是访谈上限。关键未知仍存在且继续问有望获得有效新信息时可继续；不问已知答案、不靠重复改写问题续问，新答案冲突只重开受影响决定。用户无更多事实或问题已清楚时及时按下述结果结束，不机械凑轮数。
6. 新发现权限、金额、历史数据、迁移等风险，按主技能调整实际证据要求；追问不替代运行验证。需要交互工具时只使用宿主可用能力，没有弹窗工具则用普通文字，不虚构工具调用。

## 结束结果：已澄清或暂时无法澄清
停止提问不等于达成共识；结束时区分以下结果，不新增任务状态字段。

### 已澄清
关键决定足够明确，按已有授权设计或继续。依据不是题目问完或用户笼统说“可以”，而是：
- 当前结果能用角色、起始状态、操作和可观察结果的正常示例说明；适用时有关键拒绝/失败示例。
- 一句反例说明本片不承诺什么；关键术语的含义及容易混淆的概念已区分。
- 负责模块、对外承诺及选择理由可以写入当前约定；初始化时影响当前架构和依赖实现的跨片决定已解决。
- 剩余未知仅影响可逆细节，或已标明不阻塞部分的验证/决策安排。安全边界、重要业务及高代价技术未知仍阻止依赖实现；不把它们偷偷改成默认假设。

### 暂时无法澄清
仍有重要事实缺失，且用户无法补充、现有资料不能解决或本次交互资源已耗尽时，停止重复提问，交付带来源、假设及未决项的条件方案。安全边界、重要业务和高代价技术未知仍阻止依赖实现；只推进已授权且不依赖缺口的部分。不得把“问不下去”改写为“已澄清”，也不得把条件方案当成批准。获得新事实后只恢复相关决定。

把正常示例和边界/不做的反例合并到现有关键方案展示中，不额外增加一轮审批。用户仅同意调查方向不是批准实施；同一具体方案已有批准则复用。结束追问后按已有授权设计或实施，不自动获得修改权限。

## 记录与边界
答案、重要决定、理由和行为示例写回同一份当前验收约定；跨任务成立的规则及其对外承诺进入薄基线，不新增重复 BDD 文档。未确认的写成建议/未知，不因写入文件变为已批准规则。
恢复时以相关代码和业务例子核对理解；发现实质冲突才再问，不重问历史答案。记录帮助恢复共识，不保证模型已经理解。
访谈不能代替真实用户需求验证、实现测试或生产证据；结束追问不代表 GREEN。
