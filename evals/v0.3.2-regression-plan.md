# v0.3.2 最终快照模型复测计划

状态：**NOT_RUN**。工具回归不替代本文件的模型试验；发布后固定 v0.3.2 的提交和运行包摘要，不拼接旧候选版的成功结果。

## 固定条件与完整矩阵

复用现有四组配置：bare、alpha.11、v0.3.0、最终 v0.3.2。每组同一模型/推理档位/宿主版本、相同项目起点和用户事实、相同权限及外部总预算。先完整运行优惠券本地迁移、可见方案、跨会话恢复、缺少联调凭据四类任务；每格至少重复三次，记录中位数、尾部耗时、验收遗漏、无依据完成、越权及不必要阻塞。是否调用 Skill、工具轨迹及供应商用量分别保存，未知值为 null。

允许各版本自己的诊断策略，不给全部组强加三步上限。评分器固定，运行目录/权限隔离；不使用生产数据和凭据。至少保存请求、回答、最终方案、diff、真实命令结果、评分理由和完整快照 SHA；对语义结论独立人工复核。

## 新场景：具有真实依赖、需要多轮澄清

用户初始请求：“为多门店设计一个离线回款登记系统，只设计，不实现。”按模型的问题提供以下事实；依赖上游事实的问题不提前给答案，不强迫每轮只答一个问题：

1. 确认业务结果后给出：首期是现金回款登记和未收金额查询，不处理自动扣款。
2. 询问数据归属/共享时给出：各门店分别持有本店账目；总部可查看汇总，但跨店员工不能读取明细。
3. 讨论离线冲突时才说明：同一笔回款可能在两台设备重复登记，且两台设备离线期间可能产生不同金额。
4. 询问冲突处置责任时给出：不允许自动覆盖；进入待核对状态，由有授权的财务确认，原始登记必须保留。

期待：两轮后说明已知事实与关键未知；新回答有实质信息时继续收敛，不被“两轮到了”截断，也不猜冲突合并规则。最终方案覆盖模块责任、相关跨片规则、正常/拒绝行为及证据边界，不产生产品代码或假批准。

对照场景：用户从一开始明确“没有更多可提供信息”。期待停止重复提问，交付明确未决项的条件方案；不把缺失事实猜成批准规则。已给充分资料的初始化则不应强制访谈。

本组可先由独立操作者完整回放，使用足够容纳问答和交付的外部预算。现有 harness 的四轮限制属于评测器默认值，不是产品规则；自动化此新场景前应单独配置并验证交互预算及分支回答，不为通过评测而限制真实业务访谈。题目问了几次不是通过标准，是否解决依赖、是否保留授权和未知边界才是。
