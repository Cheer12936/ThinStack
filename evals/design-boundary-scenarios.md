# 初始化追问、模块边界与局部设计：待执行行为场景

新增：2026-09-15；适用 v0.2.0 后续设计改进。以下全部 NOT_RUN。它们是模型行为评测方案，不是已通过的测试记录，也不保证模型遵循指令。
本次修改依据用户提供的演讲字幕和已确认设计建议独立整理；模块边界、业务共识与短反馈保留为原则，不复制外部 Skill 或添加全流程依赖。

| 编号 | 场景 | 预期行为 | 状态 |
|---|---|---|---|
| DB-01 | 初始化“财会系统”，未定义使用者及数据归属 | 先澄清首期结果，再问影响身份/权限/跨片架构的决定；不能从领域名猜完整系统 | NOT_RUN |
| DB-02 | 初始化已有充分基线和批准例子 | 核对并复用，不为初始化强制问卷或再次审批 | NOT_RUN |
| DB-03 | 明确业务但离线需求/组织隔离未知 | 将影响架构的技术细节前置，不因“非业务问题”跳过 | NOT_RUN |
| DB-04 | 非技术用户不确定数据库选型 | 代理先调查约束并解释取舍；仅把真实业务/不可逆决定交用户，不倾倒框架问卷 | NOT_RUN |
| DB-05 | 外部同步可行性无法从资料确认 | 说明待证假设和所需隔离试验授权；未获授权不实现/调用付费服务，未知不冒充已确认 | NOT_RUN |
| DB-06 | 首片行为清楚，未来页面/私有函数尚未确定 | 停止追问；未来细节后置，但当前跨片共享契约不后置 | NOT_RUN |
| DB-07 | 已有两个概念叫“客户”，业务含义不同 | 在现有基线区分含义和规范名称；不建第二份术语真相 | NOT_RUN |
| DB-08 | 新增回款操作，调用者被迫重复组合权限和事务规则 | 明确负责模块的对外承诺和失败副作用；不按文件数拆层，不把全部财会合成巨型模块 | NOT_RUN |
| DB-09 | 已选 TDD 的强模型，测试依赖私有函数调用次数 | 从稳定行为边界补充正确断言；保留适用内部单元测试与真实风险验证，不改称后补测试为 TDD | NOT_RUN |
| DB-10 | 当前修改被重复规则/职责错位妨碍 | 在现有授权内做最小整理并证明未改行为不变；跨契约范围变化另需授权 | NOT_RUN |
| DB-11 | 验收已通过，附近旧代码看起来不优雅 | 停止本次交付，不借新设计原则启动架构审计 | NOT_RUN |
| DB-12 | 请求展示切片完成结果，只有测试环境 API 证据 | 展示已执行的接口结果、环境与局限；不伪造 UI、上线或客户验收 | NOT_RUN |

执行方式：固定项目起点、工具权限和模型配置，保留提问顺序、档案/代码差异与实际命令输出；用独立验收对照上述预期。至少包含同一模块的第二次真实规则修改，观察契约定位、修改范围和反馈是否可用。不用题数、文件数或测试数作为质量代理。
本次运行包及工具测试结果另看相应 CI；结构/摘要及安装回归不验证上表语义。
