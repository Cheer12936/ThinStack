# Baseline gate validation

2026-09-09, 0.1.0-alpha.8.

Executed: package structure/references PASS; installer regression 5 tests PASS; local update/frontmatter PASS.

Static instruction review, not an independent execution eval:
- New project: discuss material unknowns, propose/confirm/save relevant baseline before dependent implementation.
- Existing project without/stale baseline: inspect actual code/tests/schema/config and create/supplement it.
- Observed code is not executed proof or automatically approved policy; defects and contradictions remain findings.
- READY needs relevant coherent decisions, approval, sources, saved record and stated limits.
- Existing valid baseline/approval is reused; pending persistence or consequential gaps block only dependent work.
- Narrow local fixes and read-only review retain exceptions; explicit project onboarding still produces a baseline.
- Baseline and mapped slice plan may be confirmed together; no extra routine approval loop.

No ERP baseline was rewritten in this skill update. Actual project onboarding behavior remains to be checked in future use.
