# ThinStack · 薄栈 v0.2.0

**统一交付标准，不统一实现步骤。** 唯一技能仍为 `ts-code`：用任务分流、持久基线、当前验收约定和按需指导，交付可证明的业务结果。

本版不按模型品牌固定“强弱”。默认自主，用户可指定引导；出现可观察的失控信号才增加脚手架。两种方式共享权限、风险与证据底线。版本号不表示已获得跨模型或生产安全认证。

## 安装与升级

获取仓库后，从客户端设置确认其技能目录；不要把整个仓库放入技能发现目录。

```text
git clone https://github.com/Cheer12936/ThinStack.git
cd ThinStack
python tools/manage.py install --skills-dir "你的客户端技能目录"
```

已安装的用户：先更新仓库，再执行更新，不能仅覆盖 SKILL.md。

```text
git pull --ff-only
python tools/manage.py update --skills-dir "你的客户端技能目录"
```

工具使用 Python 3.10+ 标准库，不猜客户端目录、不修改客户端配置。install 拒绝覆盖；update / uninstall 将完整旧目录移到技能目录外的备份位置并输出路径，不删除自定义文件。新目录不会遗留旧流程参考文档。恢复时先归档当前版本，再将备份复制回原位置。

也可手动复制 `skills/ts-code` 整个文件夹，并刷新技能列表。核心技能不依赖 Python，只有安装、校验和可选证据脚本需要它。

## 怎么用

```text
$ts-code 修复这个回访列表问题，保持现有权限与数据规则。
$ts-code 初始化库存项目，先确认第一个可用结果和薄基线。
$ts-code 增加一个业务切片：员工能筛选待回访客户。
$ts-code 先用引导模式，逐个小目标验证；不要重复已批准的方案。
$ts-code 先追问会改变业务方向的问题，把行为和边界写进当前约定。
$ts-code 按已有基线和任务记录继续，不重做已验证模块。
$ts-code 建立项目总览与切片档案，沿用已有入口，没有则创建 docs/SLICES.md；本次只建档。
$ts-code 只设计下一可执行切片，复用已有基线，暂不写产品代码。
```

“只设计”“只审查”“只验证”保留原授权边界。新项目和新功能默认确认一次关键方案；已批准同一方案或明确要求直接实施，不再确认。

默认关闭隐式调用，避免一般编程问答误触发。在支持 `agents/openai.yaml` 的宿主中，`allow_implicit_invocation: false` 保留显式调用；其他宿主可能忽略该元数据，应以其文档为准。

## 用户能感受到什么

| 类型 | 工作体验 | 留下什么 |
|---|---|---|
| FAST_FIX（修复） | 直接定位、窄范围修复、验证后停止 | 简短当前承诺与证据 |
| PROJECT_INIT（新项目） | 先明确首个结果与重要决定，再搭建 | 薄基线与首片路线 |
| SLICE（业务切片） | 围绕能使用的结果交付，不按技术层分工 | 当前约定、模块修改理由与验收证据 |

开工用一句话显示类型和自主/引导方式；风险变化、切片切换或阻塞时说明进展；交付说明实际结果。LIGHT / STANDARD / FULL（轻量/标准/强化）保留在内部，不要求每次播报。

## 共享骨架，按需展开

自主模式：相关基线与当前约定 → 自主实现 → 风险匹配的验证 → 交付。
引导模式：恢复同一约定 → 一个小目标 → 一个一致修改及检查 → 记录证据 → 下一个目标。

工作类型、授权、设计深度、验证深度和执行方式是独立维度。权限修复可以是小设计但强化验证，不必生成完整架构方案；强模型处理高风险任务也不能减弱证据。

- BDD（行为驱动开发）：重要歧义时追问，得到行为示例；不强制问卷或固定句式。
- SDD（规格驱动开发）：保存当前关键规则、接口和重要决定，不预先规格化整个未来系统。
- TDD（测试驱动开发）：可复现缺陷与可自动验证的关键逻辑优先测试先行；简单视觉或文案不强制，但必须验证。

需要多少约束，加载多少参考。不是要求模型每次调用三个独立技能。

## 初始化追问与模块设计

初始化不是“只问第一片”，也不是“提前问完全部实现”。先核对首期结果、组织/数据归属、权限、外部兼容、在线/离线与实际运行约束；这些决定会影响架构时必须在依赖实现前解决。已有充分答案直接复用，仍有关键未知才沿决策树深入追问。

默认一问一答，提供具体选项、主要后果与有依据的推荐。技术事实代理自己查，技术方案先给取舍；不能把选框架的问卷丢给非技术用户。未知技术可行性需要获授权的最小隔离试验时，明确试验范围，不把多问当成证据。

先明确跨片规则与模块对外承诺，再细化当前片；未来页面、私有函数和可逆细节按需后置。正常示例、拒绝/失败示例及一句“不承诺什么”合并到现有方案中检查共识，不增加审批轮次。详见[追问规则](skills/ts-code/references/clarify.md)。

基线按需记录模块对外操作、输入/结果、数据与规则归属、内部隐藏的复杂性和失败副作用；切片只写变化并引用稳定规则。深模块不等于大文件，更不是把无关职责全部合并。

测试优先验证稳定行为边界，保留适用的内部单元测试和真实风险证据。TDD 服务设计与反馈，不只是弱模型辅助。当前实现/验证确被职责错位或重复规则妨碍时，可在授权范围内最小整理并用回归保护；验收后不另开全局架构审计。

交付先展示用户能完成的动作、实际运行证据、环境和未验证边界，再链接详细档案。技术切片可以展示接口或命令结果；进度表、测试数量和软件验收都不能冒充商业收益。

## 项目记忆：一个总览，每片永久留存

客户和 AI 共用项目总览：沿用已有 `slice.md` / `docs/SLICES.md` 或其他统一入口，没有时默认 `docs/SLICES.md`。它展示目标/本期范围、可用能力与环境、模块与切片地图、全量进度、阻塞和下一步，模板为 `assets/project-overview-template.md`。

创建入口分两类：显式要求建立/更新项目总览时只做获授权的建档；初始化项目或新业务纳入已确认计划时，在依赖实现前建立/更新总览和每片记录。纯讨论/只读审查不写文件，小修复不启动全项目建档。无需另装一个切片技能。

每片有稳定编号及永久入口，沿用现有 SPEC/RUN/独立章节，无既有布局时可用 `docs/slices/<编号>-<简名>.md`。`task-template.md` 是空白格式，不是会被下一片覆盖的“当前任务便签”。未来片先留下目标、依赖、状态和批准范围；只详细设计当前准备实施的片。完成或取消后保留档案与证据。

新业务行为、独立可验证的技术模块、重要契约变更，以及后续片开始实施前需要相应设计；已有充分设计直接复用。模糊的“财会模块”先追问业务结果，再拆片；普通辅助函数、文案、样式或窄范围修复不因文件变化重新设计。只设计不授权实施，已有同一具体方案不重复审批。

长期基线保存模块职责、术语、身份/归属、关键规则和决定理由；沿用已有架构文件，没有时可用 `docs/architecture/BASELINE.md`。每片档案保存为什么改、验收、模块理由、设计增量、实际状态和证据。总览进度从档案汇总，先更新档案再同步总览，不维护两套状态。

验证通过、客户验收与上线分别记录；阻塞不抹掉原执行阶段，过期证据标记需重验。可以报告“8片中3片已验证”，不能把切片数量比例冒充工期完成率。此版由代理按档案同步汇总，未新增自动后台进度服务。

恢复顺序：总览 → 当前片档案 → 相关基线 → 必要依赖/证据 → 核对代码。已完成模块只因新需求、真实故障、失效证据或相关规则变化重开，保留原理由和历史。文件保存不保证模型必然读取，宿主仍须提供文件访问；客户分享材料需脱敏。

## 运行包

```text
skills/ts-code/
  SKILL.md                 # 薄核心
  agents/openai.yaml       # 显式触发与界面元数据
  references/
    memory.md              # 基线、当前约定、恢复
    clarify.md             # 按需追问与行为澄清
    guided.md              # 引导与返回自主
    tdd.md                 # 测试先行的条件和边界
    risk-proof.md          # 实际风险的证据底线
  assets/                  # 项目总览/薄基线/切片档案模板与原图标
  scripts/check_evidence.py # 可选证据完整性检查
  LICENSE
```

旧版 16 份运行时参考文档已整合；历史演示与评估保留在仓库，不加载进技能。详见[迁移说明](docs/MIGRATION-v0.2.0.md)。

## 检查与证据

```text
python tools/validate.py
python -B -m unittest discover -s tests -v
```

更新运行包后，由维护者显式执行 `python tools/validate.py --write-checksums` 再提交清单。`SHA256SUMS.json` 从本版起仅覆盖安装的运行包，不是整个仓库，也不是签名或安全认证。校验器检查本包输出的简化元数据格式、链接、字节预算和摘要，不声称支持完整 YAML 规范。

可选[证据记录格式](docs/EVIDENCE.md)检查来源文件及日志摘要、覆盖关系、失败/跳过状态和未解决高风险；不会执行记录中的命令。返回记录有效不等于验收充分、运行真实或软件正确。

## 验证范围

[本版验证记录](evals/v0.2.0-validation.md)区分实际执行与待测项目；[项目记忆场景](evals/project-memory-scenarios.md)及[初始化与设计边界场景](evals/design-boundary-scenarios.md)另列后续变更的待测行为。当前没有证明强模型/弱模型成功率、耗时或 Token 优势的对照实验。引导切换是模型指令，不是独立监控服务，也不能可靠识别服务端路由变化。

安全依赖宿主权限、隔离环境、真实测试和必要批准，不能仅靠提示词。模型无法取得可信证据时必须报告缺口，而不是保证自动修复一切。
