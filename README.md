# ThinStack · 薄栈 v0.3.0

**统一交付标准，不统一实现步骤。** 一个 `ts-code` 技能，按任务交付可证明的业务/技术结果，保留项目基线、每片修改理由和永久记录。

v0.3.0 将部分纪律变成可执行检查：新增项目 doctor / 总览生成、六任务三组评测框架，以及集中加载表和项目级接入说明。它不是自动证明系统正确的安全平台；真实模型对照仍需实际代理、环境和独立复核。

## 安装与更新

```text
git clone https://github.com/Cheer12936/ThinStack.git
cd ThinStack
python tools/manage.py install --skills-dir "你的客户端技能目录"
```

已有安装：

```text
git pull --ff-only
python tools/manage.py update --skills-dir "你的客户端技能目录"
```

整体更新，不只覆盖 SKILL.md。Python 3.10+ 标准库；核心指令不需要 Python。install 拒绝覆盖，update/uninstall 先把旧目录完整归档到技能发现目录之外，保留自定义文件；不自动清理备份、不修改宿主配置。不把整个仓库装进技能目录。

也可复制 `skills/ts-code` 整个目录。保留旧版备份，更新后刷新客户端技能列表。v0.3.0 不自动迁移客户项目、重排编号或升级历史“完成”状态。

## 怎么用

```text
$ts-code 修复这个回访列表问题，保持现有权限与数据规则。
$ts-code 初始化库存项目，先明确跨片关键决定、首个结果和薄基线。
$ts-code 增加一个业务切片：员工可以筛选待回访客户。
$ts-code 按已有总览和切片记录继续，不重做已验证模块。
$ts-code 建立项目总览与永久切片档案；本次只建档。
$ts-code 只设计下一可执行片，不修改产品代码。
```

默认自主，用户可指定引导；出现实际跑偏可缩小步长，不按模型品牌判断强弱。新项目/新业务默认确认一次具体方案；已批准同一范围不重复确认。只读、设计、验证和实施的授权不同，生产写入、破坏性操作、付费与部署不得由普通本地任务授权推导。

## 工作方式

| 类型 | 客户看到什么 | 保留什么 |
|---|---|---|
| 修复 FAST_FIX | 直接定位、窄范围修复、验证后停止 | 短验收约定与证据，不启动全局建档 |
| 初始化 PROJECT_INIT | 先澄清影响架构的决定，只细化首片 | 薄基线、全局切片路线、首个可用结果 |
| 切片 SLICE | 围绕独立业务或技术结果实施 | 负责模块、修改理由、关键设计与证据 |

设计深度与验证强度独立：小权限修复仍需真实权限边界验证，不因此生成完整架构文档。初始化问透跨片高代价决定，可逆实现细节后置；通过例子核对共识，不穷举所有未来页面。深模块是清楚接口封装相关复杂性，不是大文件；允许有事实依据的必要局部整理，不夹带无关重构。

BDD（行为澄清）、SDD（关键规格）、TDD（测试先行）按实际需要使用，不固定串行。TDD 在实现前选择，既服务强模型也服务弱模型；安全和数据风险不因“原型”而免除。交付先展示实际可操作结果、环境与未验证边界，而不是只展示文档或测试数量。

## 项目记忆

**总览管全局，切片档案管本片事实，基线管长期规则，证据支撑验证。**

沿用已有 `slice.md` / `docs/SLICES.md` 或任务系统。没有时默认总览 `docs/SLICES.md`，基线 `docs/architecture/BASELINE.md`，每片可用 `docs/slices/<编号>-<简名>.md`。模板只在建档时参考，不在技能安装目录写客户数据。

每片稳定编号，完成/取消后保留，编号有空洞是历史可追踪性的结果。未来片先登记目标、依赖和阶段，当前片才细化。恢复从总览进入当前片，再读取相关基线/依赖证据并核对代码，不全量重读历史。验证通过、客户验收和上线分别记录。

## 新增：项目检查与总览生成

[完整协议与字段](skills/ts-code/scripts/PROJECT_STATE.md)。显式接入 `.thinstack.json` 后，在现有 Markdown 内添加小型 JSON 状态块；配置只保存路径，不维护第二份进度。旧非结构化档案会显示未适配，不强制迁移或虚报已检查。

```text
python skills/ts-code/scripts/project_state.py doctor --root "客户项目目录" --json
python skills/ts-code/scripts/project_state.py sync --root "客户项目目录"
python skills/ts-code/scripts/project_state.py sync --root "客户项目目录" --write
python skills/ts-code/scripts/project_state.py doctor --root "客户项目目录" --require-verified S-001
```

doctor 只读，sync 默认预览；只有 --write 刷新标记生成区，保留手写内容和历史。检查重复编号、死链、依赖、基线引用版本、正式验收与报告覆盖、证据摘要及总览过期。写入有协作锁和源版本复核，不能承诺对任意外部进程的完整事务。

输出“证据匹配”不是实际执行认证或产品 GREEN：它不执行报告中的命令，不理解所有自然语言业务矛盾，不证明来源清单完整；哈希也不能阻止同权限伪造。真正的放行依赖客户项目实际测试、独立 CI、受控检查来源及必要审查。安装不会自动配置这些权限。

可在新空目录实际体验一条本地链路：

```text
python -B examples/project-state/demo.py --root "新的空演示目录"
```

它真实运行一个算术小程序的三项测试，绑定结果并生成总览。不是财务系统或客户项目验收。

## 新增：最小对照评测

[评测使用说明](evals/harness/README.md)。六任务：修复、模糊初始化、业务行为、权限、恢复和联调条件缺失；三组：不加载技能、默认自主、引导。固定起点，随机化顺序，重复运行，保留原始请求/响应、改动、评分及真实计量（未知为 null）。

```text
python -B evals/harness/run.py selftest --output "新的自测目录" --repeats 3
```

此命令运行 54 个正控制和 54 个负控制，**不是模型基准**。真实模型使用操作者明确配置的代理适配器，需 `run --adapter ... --ack-execution`；默认没有模型调用或费用。语义题保留人工复核标记；无依据宣称完成与不必要阻塞都记录。工作目录隔离不是 OS 沙箱。

## 加载与项目级启用

主文件用一个信号表选择五份参考，不叠加重复工作流；模板仅在新建时使用。[项目级接入说明](docs/PROJECT-ADOPTION.md)提供 AGENTS.md / CLAUDE.md 片段及宿主设置注意事项。

标准包的 `agents/openai.yaml` 保持禁止隐式调用；不是所有宿主都支持它。项目自动使用必须由用户启用，并验证对应宿主的调用开关、路径及权限；不能仅写一句入口就宣称一定自动加载。不复制整份 Skill 为常驻上下文。

```text
python tools/context_budget.py
```

输出主文件、五份参考、三个模板和工具文档的字节/字符规模。可显式提供已安装的 tiktoken 编码；未计量 Token 则返回 null，不从字节推算费用。静态总量不等于整个会话成本。

## 验证与边界

```text
python tools/validate.py
python -B -m unittest discover -s tests -v
```

维护者修改运行包后显式执行 `python tools/validate.py --write-checksums`。摘要覆盖安装包，不是签名；它验证包结构，不证明模型行为。[v0.3.0 交付记录](docs/RELEASE-v0.3.0.md)区分工具测试、框架自测和真实模型对照。

旧版演示、迁移文档、待测场景与 [CHANGELOG](CHANGELOG.md) 保留；不把历史结果套用到新版本。没有新增自动降级控制器、后台监控或备份自动删除功能。客户材料应脱敏；重要操作由宿主权限和真实验证共同保护。
