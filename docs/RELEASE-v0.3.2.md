# v0.3.2 · 登记安全与追问检查点

基于 `e610b155b59996cfbb6d5bc8d3f9b3e358da9d05` 的定向修补。保留统一总览、永久切片、FAST_FIX 诊断预算、七项方案底线、项目调用配置及所有旧版档案；不移动已有发布标签。

## 修复范围

- `add` 与 `sync --write` 共用协作锁，在读取档案和分配编号前加锁；只回滚本操作仍持有相同内容的文件。发现他人修改时保留现场并报告冲突，不覆盖外部编辑。
- 无配置时先检查已知旧入口和已有切片目录，要求明确适配后再登记，不创建第二套总览/基线。
- 沿用单一明确的编号序列、补零宽度及既有目录；多序列/多目录通过 `--id`、`--record-dir` 解决歧义，不重编号或迁移历史。
- 新档案的阶段、依赖、批准及正式验收只维护在机器块；正文写目标、理由、设计和历史，不再生成第二份当前状态。
- 新片默认不锁定全部基线版本。当前设计准备好后再绑定相关规则；登记时可用 `--baseline` 明确选择已登记的基线。不清空旧片的绑定或证据。
- Grill 的两轮硬上限改为信息检查点；有新信息且关键决定仍未知时继续追问，无新事实时输出条件方案并保留依赖实现的阻塞。

## 实际验证与复现

原版五个登记问题已在精确 Git blob `883c2cd0bf6c39fd6ba360a97260d4d0712b8c54` 上重现。新增 36 项隔离回归覆盖入口、编号、单一状态、延后基线、锁竞争、写入故障和并发回滚，在本地 Linux / Python 3.13.5 全部通过。

```text
python tools/validate.py
python -B -m unittest discover -s tests -v
python -B -m unittest discover -s tests -p test_registration_safety.py -v
```

完整旧测试、演示、评测器正反控制和跨平台运行，以本版提交的 GitHub Actions 结果为准；不把本地定向测试冒充全部测试或 Windows 实测。运行包与 SHA256 清单随版本更新，安装/调用逻辑未修改。

## 模型评测边界

本环境没有可用的 Codex/Claude CLI 工具代理，本版真实模型对照 **0 次，NOT_RUN**；v0.3.1 的模型成绩保留在原记录中，不拼接或继承为本版通过。完整最终快照复测和需要两轮以上澄清的场景见 [回归计划](../evals/v0.3.2-regression-plan.md)。本版不声称速度、Token 或成功率提升。

## 兼容与恢复

旧项目继续使用既有 `.thinstack.json` 及路径，不批量改写历史正文。仅未来通过 `add` 创建的记录采用单一状态正文；旧正文中重复状态需经核对后处理，不能删除真实历史。没有采用机器档案的项目仍可用人工 Markdown。

`add` 的成功只表示登记完成，不代表整项目或产品已验证；返回的 `project_result` 可显示既有问题，交付前仍运行 doctor。检查器只能核对已声明输入、验收和文件关系，不能确认规则充分性、批准真实或实际测试执行。

协作锁不是针对任意进程的操作系统事务。不同版本写入者不得混用；外部进程可能绕过协作锁。崩溃可能保留锁/部分文件，回滚冲突会保留现场：先核对配置、档案和总览再人工恢复，不删除未知锁或盲目重试。条件方案不是同意默认业务规则，更不是实施授权。
