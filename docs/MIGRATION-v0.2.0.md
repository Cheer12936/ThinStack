# 从 v0.1 升级到 v0.2.0

仓库和调用名不变：ThinStack / ts-code。此次是运行政策重构，不是另建第二套强弱模型技能。

## 保留
任务分流、独立设计/验证深度、一次方案确认、真实授权边界、项目基线、当前验收约定、历史编号、风险证据、安装归档机制。

## 改变
- 默认显式调用；主文件以中文为主。详细参考只在相应条件下加载。
- 自主/引导共用验收；引导依据用户选择或可观察表现，不依据模型品牌。
- 不再规定三次诊断上限，不强制每个功能填写 13 章方案或逐次播报档位。
- 保留薄基线的持久化与相关内容读取；不以统一文件名或 READY 标签制造全项目门槛。
- Green Contract 增加明确的修改理由与模块责任；长期任务持久保存，小修复可在对话中。
- BDD、SDD、TDD 按需使用；测试先行在实现前决定，高风险验证不因自主模式被省略。
- 旧 16 份 references 整合为 memory / clarify / guided / tdd / risk-proof。旧版本可从 Git 历史恢复。
- 结构检查改为版本文件、主文件 UTF-8 字节预算、实际链接和运行包摘要；字节不等于 Token。
- SHA256SUMS.json 仅覆盖 skills/ts-code；已删除的旧参考不会留在新清单。

## 升级操作
更新仓库后运行 `python tools/manage.py update --skills-dir "你的客户端技能目录"`。工具归档整个旧安装，再放入完整新版；不要直接合并覆盖目录，以免旧文件仍被加载。
自定义内容保存在备份里，不自动混入新版。保留既有项目基线与任务文件，不重排编号，不重写历史验证状态。
客户端刷新后核对 ts-code 的版本与显式触发。某些宿主不读取 openai.yaml，应单独配置触发方式。

完整旧方案模板不再是默认交付要求。用户明确要求详细设计时，仍按实际需求提供，不用精简版拒绝必要信息。
